> 本文档只固化**已裁定**的产品骨架与开放问题清单；标注 🎨/🎲 的部分是宠物团队（你）的自由设计空间，本骨架不预设答案。

---

## 1. 愿景与定位

- 一款**长在桌面上的宠物 RPG**：平时是桌面上的一只活着的宠物，点开是完整的游戏（属性、装备、换装、桌面上的 RPG 操作）。
- 与工具箱平台是**对等伙伴**：宠物是 Steam app 主体；平台是它的设置面板、属性查看器与快捷工具提供方。
- 迭代哲学：**底层（PetLink）冻结、上层自由**——RPG 内容高频迭代永不触碰协议层。

## 2. 目标平台与用户

- Windows 首发（Godot 导出目标）；macOS/Linux 为后续导出项（协议与设计不设障碍）。
- 用户：自己（首个版本的用户与开发者是同一人），产品设计以"我会天天用"为第一标准。

## 3. 核心体验：三模式（已裁定规格）

| 模式 | 交互 | 技术要点 | 协议可见 |
|---|---|---|---|
| **勿扰模式** | 鼠标全窗穿透，纯观赏 | `window_set_mouse_passthrough` 全窗 | 仅模式值 |
| **游戏模式** | 鼠标键盘可操作，桌面即游戏场景（RPG 操作） | 穿透关闭；桌面坐标即世界坐标 | 仅模式值 |
| **陪伴模式** | 平台快捷工具与热键的入口（如：宠物菜单点"截图"→ 平台执行） | 经 `tools.invoke` 触发平台工具 | 模式值 + `tools.invoke` |

- 模式切换入口：宠物自绘（右键菜单/热键/点击区域）🎨
- 无平台连接时三模式依然成立（陪伴模式中平台工具项静默隐藏）

## 4. RPG 系统轮廓（骨架级，全部 🎲 自由设计空间）

| 系统 | 骨架问题（立项时要回答的） |
|---|---|
| 属性系统 | 有哪些主/副属性？成长曲线？时间挂机还是操作驱动？ |
| 装备系统 | 槽位模型？稀有度？获取途径（桌面行为掉落？） |
| 换装系统 | 部件分层（身体/头饰/背饰…）？渲染分层与动画兼容怎么做？ |
| 桌面 RPG 操作 | "在桌面上进行 RPG 操作"的具体形态：桌面寻路？点击事件？窗口交互？ |
| 经济与进度 | 货币/经验来源绑定哪些桌面行为？防刷设计？ |
| 状态呈现 | 疲劳/心情/饥饿类机制要不要？（影响"宠物活着"的观感） |

**已裁定的硬约束**：存档走 `user://` + Steam Cloud（时间戳胜出+本地副本）；数据模型演进自由（平台永不感知结构）。

## 5. 与平台的关系（全部已裁定，不可自由发挥）

- 联动只走 PetLink（协议规范见平台仓 `docs/protocols/petlink.md`）；
- 宠物**不做设置界面**——设置项以声明式表单 schema 提供，平台渲染（`pet.settings-schema` / `pet.settings-apply`）；
- 属性/装备/进度对平台是只读快照（`pet.state`）；
- 独立模式完整性是验收标准：拔掉平台，游戏全功能可玩；
- 永不触碰平台文件系统；永不经协议外方式操纵平台（边界绝对律 §1.2）。

## 6. 非目标（v1 明确不做）

- 设置 UI（平台承担）；
- 工具箱功能（截图等归平台，宠物只做入口）；
- 多宠物同屏（未裁定，留 v2+）；
- 移动端；
- 联网/多人（存档云同步除外，那是 Steam Cloud 的事）；
- 故事/图鉴的平台侧呈现（协议留口子：`pet.state` 可扩展静态数据包，v1 不实现 🎨内容先行活在 Godot 内）。

## 7. 里程碑建议

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| **P0 PoC（2-3 天）** | TCP 帧对拍（用平台仓 echo 夹具方法）/ 透明+置顶+无边框窗口 / 点击穿透 / 反向唤起哑平台 | 四件套全绿 → PetLink 升 v1.0 定稿 |
| **P1 垂直切片** | 一只宠物 + 桌面行走 + 三模式切换 + 独立模式验证 + PetLink 握手/配对跑通 | "拔平台全功能可玩"成立 |
| **P2 RPG 核心** | 属性 + 换装（分层渲染）+ 至少一条进度线 + Steam Cloud 配置 | 属性面板在平台侧可见 |
| **P3 打磨与上架准备** | 美术方向落地 🎨 + Steam 商店资产 + 同捆打包管线（depot 组装 pet.exe + toolbox.exe） | Steam 上架提审 |

## 8. 开放问题清单（立项讨论用）

1. 🎨 美术方向与宠物形象（像素/手绘/3D？——建议 P1 前定，影响换装分层设计）；
2. 🎲 "桌面 RPG 操作"的核心玩法一句话是什么？（P1 前必须有答案）；
3. 🎲 挂机 vs 操作驱动的比重；
4. 平台侧属性面板的信息密度（P2 时与平台仓协同定 schema 细节）；
5. 仓库名与 `pet.<studio>.<name>` appId（登记进边界绝对律附录 A）；
6. Godot 版本锁定（PoC 时定，写进宠物仓 README）。
