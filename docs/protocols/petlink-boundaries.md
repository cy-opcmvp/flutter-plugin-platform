## 1. 边界绝对律（双方永久遵守）

### 1.1 平台（Flutter 工具箱）对宠物

1. **永不读写宠物存档内容**——RPG 数据（属性/装备/换装/进度/货币/设置值）物理上属于宠物的 `user://`（含 Steam Cloud 同步），平台只经 PetLink 取**快照**用于展示，不落盘、不缓存到自身持久层；
2. 平台侧持久化的宠物相关数据**仅限**：安装/发现态、全局联动开关、配对密钥、窗口位置偏好、PetLink 版本协商记录；
3. 平台不嵌入任何宠物资源（模型/动画/图片）——宠物是独立 exe，不是平台资产；
4. 平台对宠物的进程管理仅限：拉起（经 Steam 或 exe）、监督重启（仅平台自己拉起的实例）、经 PetLink 通信——**不做进程注入、不做窗口子类化、不做内存读取**。

### 1.2 宠物（Godot 游戏）对平台

1. **永不触碰平台文件系统**——不读写平台配置/插件数据/日志；
2. **永不经 PetLink 之外的方式操纵平台**——不用窗口消息、不用模拟键鼠、不用进程句柄；
3. 对平台的全部操作收敛为 PetLink 白名单动词（拒绝清单见 petlink.md §11）；
4. 宠物在无平台时必须**完整可玩**（独立模式）——任何游戏功能不得以平台在身为前提（联动增强除外）。

### 1.3 数据归属总表

| 数据 | 归属 | 对方可见性 |
|---|---|---|
| RPG 存档/属性/装备/进度 | 宠物 | 平台仅经 `pet.state` 只读快照展示 |
| 宠物设置值 | 宠物（经 settings-apply 写入宠物侧） | 平台仅渲染表单、不落盘 |
| 联动开关/配对密钥/窗口偏好 | 平台 | 宠物经 `settings.get` 读取 |
| 平台插件/工具箱数据 | 平台 | 宠物零访问 |
| 第三方 sidecar 插件（.scp） | 平台 | 与宠物体系完全隔离，互不相干 |

## 2. 命名与身份规范

| 项 | 约定 |
|---|---|
| 协议名 | `PetLink`（唯一拼写） |
| Steam app 主体 | 宠物游戏；app 名以宠物项目 PRD 为准 |
| 双 exe 命名 | 宠物 `pet.exe`（Godot 导出）；平台 `toolbox.exe`（Flutter 构建）——Steam 同捆安装布局内同目录 |
| 宠物 appId | 形如 `pet.<studio>.<name>`（小写分段，PetLink 握手必填；具体值由宠物仓 PRD 定稿时登记到本文附录 A） |
| TCP 端口 | 默认 47613（草案值，双仓同步修改才可变更） |
| 进程/日志名 | 进程名同 exe；日志通道名 `petlink.pet` / `petlink.platform` |
| 版本号 | 协议版本独立于两仓各自的产品版本（`petlinkVersion` 与 app 版本解耦） |

## 3. 各自的演进自由（绝对律保护的另一半）

绝对律同时**保护**迭代自由——以下变更**无需**对方同意：

- **宠物侧**：RPG 数值/装备/换装/动画/故事/UI/存档结构——只要 `pet.settings-schema`/`pet.state` 的返回仍合法；
- **平台侧**：工具箱一切功能/插件/UI/主题——只要 PetLink 白名单动词语义不变。

## 4. 副本同步机制（防两份漂移）

1. 宠物仓的 `docs/petlink.md` 与 `docs/petlink-boundaries.md` 是平台仓对应文件的**版本化只读副本**，副本头部必须标注来源 commit hash；
2. **同步义务**：平台仓每次修改协议文件，同一变更集内必须更新宠物仓副本（或在其 PR 中挂"待同步"标记并在宠物仓 24 小时内跟进）；
3. **校验脚本**（双仓 CI 各跑一份，逻辑相同）：
   ```text
   对 petlink.md 与 petlink-boundaries.md 计算 SHA-256（忽略副本头部的来源行），
   与对方仓最新 release tag 的对应文件比对：不一致 → CI 失败并提示同步。
   ```
4. 争议裁决：协议歧义以**平台仓版本**为准（演进宪法第 1 条：动词新增权仅平台开发者）。
