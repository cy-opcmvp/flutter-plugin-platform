# Plugin Platform v2 — post-2.0 路线图

> 本路线图收录 v1 → v2 重写后**计划重建**的旧能力与已批准的新增强项。
> 每项一句说明，并标注来源（差异清单行号见
> `docs/superpowers/cutover/v1-v2-feature-diff.md`）。排序即建议优先级。
> 定稿依据：差异清单草稿节 + F5-03 五项用户裁定
> （标签管理 / IPluginI18n / CLI `publish` → 入 roadmap；系统托盘 / 自动启动 → 彻底消失，见文末）。

## 已裁定彻底消失（不在 roadmap）

以下能力经 F5-03 逐项裁定**不重建**，差异清单「随旧代码删除而消失的能力」汇总节
中标注 `彻底消失` / `随架构消失` 的条目均不进入本路线图，明确包括：

- **系统托盘**——v1 即未落地（仅配置预留与空目录），裁定彻底消失；
- **自动启动**——裁定彻底消失；
- **权限管理**（`permission_handler` 路线）、**服务测试界面**、**开发期热重载自研包装**、
  **CLI `build`/`test`**——v1 中即无实效或由原生工具替代，彻底消失；
- 进程内插件沙盒、运行时服务定位器/平台服务管理器、`IPlugin`/`PluginContext` 开发模型、
  平台适配抽象层——由 v2 架构（sidecar 进程隔离 + SCP1、组装根注入、`PluginLifecycle` +
  能力注入、`platform_capabilities` + 条件导出）显式替代，随架构消失；
- **JSON 配置编辑器**——常规配置由声明式设置表单承担，Schema 校验与 JSON 直编不再提供；
- 旧 zh/en 全量翻译键、JS/Java/C++ 外部插件声明样本——按需覆盖 / 语言无关协议替代。

如需回溯这些能力的 v1 实现位置与放弃理由，见
`docs/superpowers/cutover/v1-v2-feature-diff.md`；v1 源码与文档存于
`docs/archive/v1/`。
